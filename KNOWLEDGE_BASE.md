# База знаний: Техническая архитектура PWA, Офлайн-режима и Обновлений

Данный документ содержит исчерпывающее техническое описание архитектурных решений, алгоритмов и механизмов, обеспечивающих установку, офлайн-работу, обновление и приветствие пользователей в приложении **Семейный Чемодан**.

---

## 1. Установка приложения (PWA Installation Logic)

### 1.1. Определение платформы и состояния установки
При инициализации приложения в `index.html` и `App.tsx` производится проверка среды выполнения:
* **Standalone-режим:**
  `window.matchMedia('(display-mode: standalone)').matches || window.navigator.standalone === true`
* **iOS устройство:**
  `/iphone|ipad|ipod/i.test(window.navigator.userAgent)`
* **Android устройство:**
  `/android/i.test(window.navigator.userAgent)`

Если приложение открыто внутри установленного PWA-контейнера (`isPwaInstalled === true`), плавающая кнопка установки и модальные подсказки скрываются.

### 1.2. Перехват нативного события `beforeinstallprompt`
1. В глобальном скрипте `index.html` регистрируется слушатель события `beforeinstallprompt`.
2. Событие предотвращается (`e.preventDefault()`) и сохраняется в глобальную переменную `window.deferredPrompt`.
3. Реализован кастомный эвент `pwa-install-available`, который уведомляет React-компонент о возможности нативной установки на Android/Desktop.

### 1.3. Сценарии вызова установки (`handleTriggerInstall`)
* **Android / Desktop (с поддержкой `deferredPrompt`):**
  При нажатии на кнопку установки вызывается `deferredPrompt.prompt()`. Если пользователь подтверждает установку, промо-событие очищается. Если пользователь отказывается или нативный промпт недоступен, открывается адаптивная модальная инструкция по ручной установке (три точки в браузере -> «Установить приложение» / «Добавить на главный экран»).
* **iOS (Safari / WebKit):**
  Поскольку iOS не поддерживает событие `beforeinstallprompt`, приложение сразу открывает специализированное инфо-окно с наглядной пошаговой инструкцией:
  1. Нажать кнопку **«Поделиться»** (иконка квадрата со стрелкой вверх внизу экрана Safari).
  2. Прокрутить меню вниз и выбрать **«На экран "Домой"»**.
  3. Нажать **«Добавить»**.

## 2. Приветственное окно после установки (Welcome Modal)

### 2.1. Условия и логика срабатывания
Приветственное окно открывается **строго один раз** и **только в установленном PWA-приложении**.

1. При запуске проверяется флаг `isStandalone` (`display-mode: standalone`).
2. Проверяется наличие записи в `localStorage`: `localStorage.getItem('hasSeenWelcome')`.
3. Если приложение запущено как PWA и флаг `hasSeenWelcome` отсутствует:
   * Состояние `isWelcomeModalOpen` устанавливается в `true`.
   * Запускается анимация салюта/конфетти через библиотеку `canvas-confetti`.
   * В окно выводится заголовок **«Поздравляем!»** и подзаголовок **«Приложение установлено и готово к работе»**.

### 2.2. Завершение приветствия
При нажатии на кнопку **«Начать»** вызывается функция `closeWelcome()`:
```typescript
localStorage.setItem('hasSeenWelcome', 'true');
setIsWelcomeModalOpen(false);
```
Это гарантирует, что при последующих запусках PWA приветственное окно больше никогда не появится.

## 3. Информационное окно обновления приложения (Update Notification Modal)

### 3.1. Детекция новой версии
Проверка обновлений выполняется двумя параллельными механизмами:
1. **Service Worker Controller Change:** При регистрации новой версии Service Worker отправляет событие `pwa-update-available`.
2. **Периодический опрос `version.json`:**
   В `App.tsx` выполняется запрос к `./version.json?cache-bust=Timestamp`. Если полученное значение `data.version` отличается от локальной константы `APP_VERSION`, активируется состояние `isPwaUpdateAvailable(true)`.

### 3.2. Интерфейс и текст окна обновления
Модальное окно обновления оформлено в едином стиле приложения и содержит:
* Заголовок: **«Приложение обновилось!»**
* Подзаголовок: **«Пользоваться стало еще удобнее»**
* Единственную кнопку действия: **[Начать]**

### 3.3. Применение обновления (`handleTriggerUpdate`)
При нажатии на кнопку **«Начать»**:
1. В Service Worker отправляется команда активации новой версии:
   `navigator.serviceWorker.controller.postMessage({ type: 'SKIP_WAITING' });`
2. Если контроллер Service Worker не активен, происходит жесткая перезагрузка страницы `window.location.reload()`.
3. Слушатель `controllerchange` автоматически обновляет вкладку пользователя, загружая актуальную версию из обновленного кэша.

## 4. Гарантированный офлайн-режим (Offline Strategy & Service Worker)

### 4.1. Гибридная стратегия кэширования (Stale-While-Revalidate + Cache First)
Для решения проблемы конфликта между обновлением приложения и его автономной работой в условиях полного отсутствия сети (включая «Режим полета») используется двухуровневый Service Worker (`sw.js`):

1. **Предварительное кэширование (Precaching):**
   При установке Service Worker (`install`) в хранилище `CacheStorage` заносятся критически важные файлы:
   * `./index.html`
   * `./manifest.json`
   * `./icon.svg`, `./icon-256.png`, `./icon-512.png`
   * `./version.json`

2. **Динамический перехват ассетов (`cacheCurrentPageAssets`):**
   При загрузке страницы в `index.html` дополнительно сканируются все подключенные `script`, `link` и `img` элементы, после чего их URL принудительно сохраняются в `CacheStorage` (`family-pack-cache-v0.0.1`).

3. **Обработка сетевых запросов (`fetch`):**
   * При получении GET-запроса Service Worker сначала ищет совпадение в кэше (`caches.match`).
   * **Если ресурс найден в кэше:** Он отдается мгновенно (0 мс задержки), а в фоновом режиме (если есть сеть) посылается запрос на обновление кэша. Если сети нет — ошибка игнорируется.
   * **Если ресурса нет в кэше:** Выполняется сетевой запрос. При успехе результат дублируется в кэш.
   * **При отсутствии сети (`Offline / ERR_FAILED`):**
     Если запрос является навигационным (`mode === 'navigate'` или `Accept: text/html`), Service Worker гарантированно возвращает скэшированный `index.html`.

4. **Защита от сбоев при проверке обновлений:**
   Функция проверки версии в `App.tsx` проверяет статус `navigator.onLine`. Если устройство офлайн, опрос `version.json` немедленно прерывается без выбрасывания фатальных ошибок, позволяя пользователю беспрепятственно работать с локальным хранилищем (`localStorage`).

## 5. Сводная таблица взаимодействия компонентов

| Компонент / Сценарий | Онлайн режим | Офлайн режим (Режим полета) |
| :--- | :--- | :--- |
| **Загрузка приложения** | Загружается с фоновым обновлением кэша | Загружается моментально из Service Worker Cache |
| **Установка PWA** | Доступна (нативный промпт / инфо-модалка) | Работает на основе заранее скэшированного Manifest |
| **Приветствие (Welcome)** | Показывается 1 раз после установки | Показывается 1 раз после установки |
| **Проверка обновлений** | Сверяет `version.json` с сервером | Проверка тихо пропускается, не мешая работе |
| **Сохранение списков** | Сохраняется в `localStorage` | Сохраняется в `localStorage` |
